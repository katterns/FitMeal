# FitMeal AI

**FitMeal AI** — небольшой сервис для расчёта дневной калорийности.
Пользователь регистрируется, пополняет баланс внутренними кредитами, заполняет анкету питания и запускает анализ.

Стек: FastAPI, PostgreSQL, Redis/Celery, Scikit-learn, Streamlit, Prometheus/Grafana.

## Возможности

Сейчас реализован основной сценарий:

- регистрация и логин пользователя;
- JWT-аутентификация;
- баланс кредитов у пользователя;
- пополнение баланса тестовой операцией;
- два тарифа: "Базовый - расчёт калорий" и "Продвинутый - рекомендация меню";
- ML-расчёт дневной калорийности;
- меню через Mistral API для Pro;
- асинхронная обработка анализа через Celery + Redis;
- списание кредитов за успешный анализ;
- история анализов пользователя;
- Streamlit-интерфейс;
- Swagger-документация FastAPI;
- `/metrics` для Prometheus;
- запуск через Docker Compose с PostgreSQL, Redis, worker, Prometheus и Grafana.

Пока не реализовано:

- Premium-тариф;
- промокоды;
- реферальная программа;
- недельное меню;
- список покупок;
- сложная админ-панель.

## Тарифы

| Режим анализа | Что входит | Списание |
| --- | --- | --- |
| Базовый - расчёт калорий | ML-оценка дневной калорийности | 5 кредитов |
| Продвинутый - рекомендация меню | Всё из базового тарифа + меню на 3 дня через Mistral API | 15 кредитов |

Кредиты списываются только после успешного анализа. Если расчёт или меню завершились ошибкой, анализ помечается как `failed`, а баланс не уменьшается.

## ML-модели

В проекте используется синтетический датасет `data/nutrition_profiles.csv`, который создаётся скриптом `infra/ml/train_models.py`.

Целевая калорийность считается по формуле Миффлина-Сан Жеора:

```text
male_bmr = 10 * weight_kg + 6.25 * height_cm - 5 * age + 5
female_bmr = 10 * weight_kg + 6.25 * height_cm - 5 * age - 161
daily_calories = bmr * activity_factor * goal_factor
```

Скрипт обучает и сохраняет одну модель:

- `models/calorie_model.joblib` - регрессия дневной калорийности;

Запуск обучения:

```bash
python infra/ml/train_models.py
```

Текущие метрики сохраняются в `models/model_metrics.json`.

## Меню

Для продвинутого тарифа сервис запрашивает у Mistral короткое меню на 3 дня:

- меню на 3 дня;
- короткое объяснение рекомендаций;
- адаптация под ограничения и нелюбимые продукты.

Для Pro-тарифа используется Mistral API. Ключ хранится только в `.env` или переменных окружения:

```env
MISTRAL_API_KEY=your-api-key
MISTRAL_MODEL=mistral-small-latest
```

Если ключ не задан или Mistral временно недоступен, задача получает статус `failed`, пользователь видит сообщение с просьбой повторить запрос позже, а кредиты не списываются.

## База данных

Минимальные таблицы:

- `users` - пользователь, email, пароль, роль, баланс;
- `transactions` — история пополнений и списаний с привязкой к операциям;
- `nutrition_profiles` - анкеты пользователей;
- `analysis_tasks` - анализы и их статусы;
- `analysis_results` - рассчитанные калории и меню для Pro.

Баланс хранится прямо в `users.balance`: для текущего объёма это проще, чем отдельная таблица балансов. Тарифы тоже не вынесены в БД: режим анализа приходит в запросе, а стоимость берётся из настроек `basic_tariff_price` и `pro_tariff_price`.

## Пользовательский сценарий

1. Пользователь регистрируется и входит в систему.
2. Пользователь пополняет баланс тестовой кнопкой, операция сохраняется в истории транзакций.
3. Пользователь заполняет анкету питания.
4. Пользователь выбирает базовый или продвинутый режим анализа.
5. API проверяет баланс.
6. API создаёт задачу анализа со статусом `pending`.
7. Celery worker забирает задачу из Redis и запускает ML-предсказание.
8. Для Pro worker вызывает Mistral API и генерирует меню.
9. Результат сохраняется в БД.
10. Кредиты списываются с баланса.
11. Пользователь видит результат и историю анализов.

## API

Основные эндпоинты:

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `POST` | `/api/v1/auth/register` | Регистрация пользователя |
| `POST` | `/api/v1/auth/login` | Получение JWT-токена |
| `GET` | `/api/v1/users/me` | Профиль: email, роль, баланс |
| `POST` | `/api/v1/billing/topup` | Пополнение баланса |
| `GET` | `/api/v1/billing/transactions` | История транзакций |
| `POST` | `/api/v1/analysis` | Создание анализа питания |
| `GET` | `/api/v1/analysis/{analysis_id}` | Получение результата |
| `GET` | `/api/v1/analysis/history` | История анализов |
| `GET` | `/health` | Проверка состояния сервиса |
| `GET` | `/metrics` | Метрики Prometheus |

## Streamlit

Отдельное приложение: вход по JWT, баланс, пополнение, анкета, запуск анализа и история (до последних записей).

## Запуск

Запуск:

```bash
docker-compose up --build
```

Имя Compose-проекта задаётся как **fitmeal-ai** (ключ `name` в `docker-compose.yml`), чтобы контейнеры и тома не смешивались с другими проектами на машине.

После запуска:

- API: `http://localhost:8000`
- Swagger: `http://localhost:8000/docs`
- Streamlit: `http://localhost:8501`
- Prometheus: `http://localhost:9090`
- Grafana: `http://localhost:3000`

## Проверка проекта

Основной сценарий проходит через регистрацию, логин, пополнение тестового баланса, запуск анализа и просмотр истории. API отдаёт Swagger автоматически, `/metrics` открыт для Prometheus, а Docker Compose поднимает API, worker, PostgreSQL, Redis, Streamlit, Prometheus и Grafana.

Тесты закрывают базовый пользовательский flow, ошибки авторизации, нехватку кредитов, ML-формулы и разбор ответа Mistral без реального вызова API.

## Бизнес-идея

FitMeal AI продаёт не подписку, а разовые анализы за внутренние кредиты. Базовый тариф подходит пользователю, который хочет быстро узнать дневную норму калорий. Продвинутый тариф дороже, потому что добавляет генерацию меню на 3 дня.
